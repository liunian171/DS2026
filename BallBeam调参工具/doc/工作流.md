# BallBeam_UNO 工作流

## 1. 事实来源优先级

从高到低：

1. 用户在当前重新开发阶段明确确认的信息。
2. ZDT 原厂资料及原厂示例源码。
3. X42S 实机返回帧和可复现测试记录。
4. DS2026 中已经确认的系统参数。
5. Git 历史仅用于追溯，不作为新实现的默认依据。

资料发生冲突时，不自行选择；在工作条目中标为“待确认”并询问用户。标准 `PUL/STEP + DIR`、`PUL_WID` 脉宽编码模式、Emm 自由协议和 MODBUS 必须分开记录和实现。

## 2. 每次操作的固定流程

这里的“一次操作”指一个可以单独验收和提交的工程变更。

1. 在 `工作条目.md` 中确认当前条目的范围、输入条件和验收标准。
2. 在 `操作日志.md` 记录操作开始、依据、计划影响的文件以及安全边界。
3. 如有协议、接线、参数或预期行为不确定，先向用户确认，条目标记为“等待确认”。
4. 只实现当前条目，不夹带下一阶段功能。
5. 先做静态检查、主机测试或编译验证。
6. 只有用户确认硬件条件和测试步骤后，才烧录并进行实机操作。
7. 将结果同步到操作日志、开发跟踪、调试记录和受影响的设计文档。
8. 验证通过后创建一个独立 Git commit；提交信息以工作编号开头。

## 3. 状态定义

| 状态 | 含义 |
|---|---|
| 等待确认 | 缺少用户必须确认的信息，不能安全继续 |
| 就绪 | 输入信息齐全，可以开始 |
| 进行中 | 正在实施，尚未完成验证 |
| 软件已验证 | 静态检查、测试或编译已通过，尚未实机确认 |
| 硬件已验证 | 已烧录并取得预期实机证据 |
| 已完成 | 达到本条目验收标准并完成文档与提交 |
| 阻塞 | 已记录明确阻塞原因，等待外部条件变化 |

## 4. 安全门槛

- 用户已授权使用代码做有限实机探测，并最新确认 D2=`DIR`、D3=`PWM/STEP`。诊断代码可以在上电锁定、有限脉冲、可停止并完整记录的条件下配置这两个引脚；该授权不等于生产控制接口或 X42S 菜单值已确认。
- 脉冲运动接口与可选通信遥测分开：遥测只能读取，不得在未另行确认时发送运动、使能、回零或参数写入命令。
- 纯脉冲方向接口是单向给定；未增加遥测时，UNO 的脉冲累计只能表示命令位置，不能作为实际电机位置或球杆角度的验证证据。
- 首次整圈测试固定为 3200 脉冲，方向和频率必须由 `RUN <0|1> <Hz>` 明确给出；没有参数时不得自动运动，`STOP` 必须可中断，完成后引脚恢复高阻。
- 电机命令和内部闭环行为完成实机验证前，不开始 PID 或串级闭环。

## 5. Git 规范

- 功能分支：`codex/zdt-emm-restart`
- 提交粒度：一个工作条目、一次验证、一次提交。
- 提交格式：`Rxx <type>: <本条目结果>`。
- 不提交构建产物、串口日志中的无关内容或其他用户文件。
