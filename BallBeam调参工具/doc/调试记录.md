# BallBeam_UNO 调试记录

本文件只记录重新开发阶段的问题。旧实现的问题保留在 Git 历史中，不作为当前设计依据。

## D-R001：MODBUS 与 Emm 自由协议存在混用风险

- 状态：已规避，待实机确认自由协议响应。
- 现象：ZDT PDF 主体描述 MODBUS RTU，而原厂 `Emm_V5.c/.h` 示例使用帧尾 `0x6B` 的自由协议，两者帧格式不同。
- 根因：资料对应不同通信协议，不能将寄存器、CRC 和自由协议命令码拼接使用。
- 处理：用户已选择 Emm 自由协议；代码、测试和文档独立维护该协议，MODBUS 资料仅用于区分协议与查找明确标注的共同概念。

## D-R002：速度上限资料不一致

- 状态：待确认。
- 现象：MODBUS 手册中的速度范围上限为 3000 RPM，原厂自由协议示例注释写 5000 RPM。
- 根因：资料版本或协议定义存在差异，当前没有实机证据确定 X42S Emm 固件采用哪一项。
- 处理：在只读通信完成前不发送运动命令；首次运动速度由用户确认或通过安全测试确定，不使用冲突值作默认值。

## D-R004：运动接口路线与用户最新说明冲突

- 状态：等待确认精确脉冲语义；已停止代码推进。
- 现象：R00/R01 文档选择了 UART + Emm 自由协议运动控制；用户最新说明当前实际采用 UNO 输出脉冲波和独立方向电平，不使用通信控制运动。
- 根因：重新开发阶段的接口结论发生更新；“PWM”还可能指标准 `PUL/STEP` 脉冲列或 V2.0.2 新增的 `PUL_WID` 脉宽编码模式，两者不能混用。
- 处理：撤销 UART 作为运动控制前提，改为脉冲方向接口待确认；当前安全空工程保持无电机输出。待用户提供脉冲语义及 `P_Pul`、`CtrlMode`、`En` 实值后才实现。

## D-R005：内部电机闭环不等于球杆角度闭环

- 状态：已明确设计边界。
- 现象：X42S 称为闭环步进电机，容易被理解为 UNO 或球杆机构已经获得实际角度反馈。
- 根因：X42S 的磁编码器测量电机轴；标准脉冲方向输入本身不向 UNO 返回实际位置，且编码器不测量齿轮齿条后的球杆角度。
- 处理：电机轴闭环由 X42S 内部完成；若需验证实际角度/误差/状态，另行确认 UART/RS485 只读遥测。当前不使用 AS5600，文档明确机械回差、打滑和实际梁角不可直接观测。

## D-R006：D5/D6/D7有限诊断未观察到电机动作

- 状态：已停止该映射测试；等待按用户最新 D2/D3接线重测。
- 现象：D6输出20 us计数脉冲累计80个，以及1500/1510/1550 us、20 ms周期的有限帧；D5分别保持高阻、低、高，K230D画面中的横杆均无可判定位移，球坐标约在-10.95至-11.00 cm。
- 根因：仅凭无动作不能区分旧引脚映射错误、X42S输入模式不匹配、使能/供电状态或接收端条件；单向引脚没有状态回读。
- 处理：不继续放大指令。用户随后明确当前接线为D2方向、D3 PWM/STEP，旧D5/D6/D7组合废止。

## D-R009：双USB连接不等于K230D与UNO已经通信

- 状态：设计上已解决，待端口实测。
- 现象：K230D和UNO都接入同一电脑，但K230D控制帧只写物理UART2 Pin 11，UNO无法从自己的USB口自动收到该数据。
- 根因：两个USB串口是相互独立的主机端设备，Windows不会自动在端口间转发数据。
- 处理：用户确认采用电脑桥接。K230D新增严格`B,...`帧USB镜像；桥接程序过滤合法帧后从COM7候选端口转发到UNO COM9。关闭IDE串口占用后再实测端口身份。

## D-R012：CanMV未保存缓冲区导致运行代码与磁盘镜像补丁不一致

- 状态：已解决。
- 现象：CanMV状态栏确认COM7连接K230D并处于“正在预览”，终端约35–38 FPS、位置约-11.16至-11.20 cm、状态TRACK；但终端没有应由磁盘版`k230_try.py`逐帧打印的`B,...`镜像。VS Code资源管理器同时显示“1个未保存的文件”。
- 根因边界：可确认当前运行输出与磁盘镜像版本不一致；未保存文件是否就是`k230_try.py`仍需用户确认，不能擅自保存、覆盖或丢弃。
- 处理：保留用户内容并等待用户保存；随后重核磁盘脚本、通过CanMV命令保存为`/sdcard/main.py`，界面明确提示保存成功。板级复位后脚本自启动，COM7连续输出严格`B,...`帧，未再覆盖用户编辑器。

## D-R013：CanMV断开和Ctrl+D不能启动当前固件的main.py

- 状态：已解决并记录当前固件行为。
- 现象：CanMV断开后COM7为0行；在`>>>`向固件v1.8-0发送一次Ctrl+D，只返回`MPY: soft reboot`、版本信息和新的`>>>`，12秒内没有控制帧。
- 根因：当前实测中，CanMV断开只释放端口，Ctrl+D软重启只回到REPL；两者均未执行`/sdcard/main.py`。不把其他MicroPython平台的通用行为套用到本板。
- 处理：通过当前固件支持的`machine.reset()`执行板级复位。复位后`main.py`自启动，18秒读取799行，其中638行为严格控制帧。后续可使用物理复位/重新上电，或已验证的板级复位方式启动。

## D-R014：自动启动后视觉状态持续为LOST

- 状态：已通过重采空轨道背景并放回钢珠关闭本次问题。
- 现象：板级复位后启动日志要求“请在60帧内移走钢珠”；随后6秒稳态采样229个严格帧，全部为`B,<frame>,0,0`，没有TRACK帧。此前由CanMV手动运行时曾观察到约35–38 FPS、位置约-112 mm、TRACK。
- 根因边界：远程复位期间没有现场操作钢珠，符合背景采集条件未满足的可能性；但当前没有重新观察现场画面，不能据此确定唯一根因。
- 处理：闭环保持禁止。用户移走钢珠后，先以单次Ctrl+C确认K230进入REPL，再执行已验证的`machine.reset()`。新一轮日志从BG 57倒计数到4，随后明确输出`BG: 空轨道背景采集完成`并持续`BG_OK`；10秒收到341个严格state=0帧，空轨道阶段无异常。用户放回钢珠后，6秒读取228帧全部为state=2，帧号连续、位置稳定-112 mm；用户同时确认视觉模块没有问题。本次视觉前置问题关闭，但不把此前LOST的唯一根因扩大为未经证明的硬件结论。

## D-R015：锁定桥接中每次出现一次非法视觉帧报告

- 状态：已在两次独立锁定桥接中复现，根因待定位；不影响当前锁定安全结果。
- 现象：第一次短时桥接统计K230输入352行、转发282帧，UNO帧号更新至3057并出现一次`ERR invalid_vision_frame`。完成空轨道背景并恢复TRACK后的第二次桥接输入330行、转发264帧，UNO帧号12451更新至12705，又出现一次相同报告；其余TRACK状态持续更新。
- 根因：当前一次样本不足以区分串口起始边界、UNO接收丢字节或其他瞬态原因，未确认。

## D-R016：第二次P控制动作未使视觉位置向中心改善

- 状态：待继续实测定位。
- 现象：基线为-112 mm，`SIGN=+1`下UNO正向运动；约+242命令脉冲期间视觉先为-113 mm，后达到-114 mm，未向目标0 mm改善。外部保护立即请求RETURN，最终命令脉冲回0，视觉也回到-112 mm附近。
- 已知条件：用户确认从当前相机画面看电机顺时针使梁左端升高；固件正请求速率输出顺时针。第二次测试的请求速率达到+200 pulse/s，UNO累计位置确实增加。
- 根因边界：2 mm变化不足以单独证明方向错误，也可能涉及视觉量化/噪声、球体静摩擦、梁响应延迟或现场机械状态；本轮没有独立测量梁角和X42S编码器实际位置，根因未确认。
- 处理：已自动RETURN并DISARM，不继续输出。后续先结合现场肉眼观察与更完整的位置时间序列确认真实响应，再决定是否改`SIGN`、保护阈值或P参数。

## D-R017：UNO命令脉冲持续累计但电机几乎不动

- 状态：菜单和16细分已确认；等待X42S侧输入脉冲/位置诊断。
- 现象：三参数自动固件已进入ARMED；`req_hz=current_hz=200`，约2.5秒内`pulse`从+726增至+1197，但用户观察电机几乎没有动作，视觉位置同时从约-80 mm恶化到-105 mm。
- 已确认的软件侧事实：471个命令脉冲/约2.5秒与200 pulse/s相符，UNO的PID、速率斜坡和命令计数正在运行。`pulse`不是X42S实际编码器反馈。
- 根因边界：实物已确认为`PUL_ENA/CR_VFOC/HOLD/MStep=16`，用户进一步确认是电机轴本身几乎不转。200 pulse/s对应3.75 rpm，但累计1197命令脉冲应为约134.7°，因此速度低、细分错误、PUL_WID和机械传动均不是完整解释。UNO软件计数不能证明脉冲已到达X42S；若已到达，还可能是校准、供电、堵转或保护状态。
- 处理：停止继续提高KP。优先读取X42S的输入脉冲数、目标位置、实时位置、位置误差和状态，或在X42S Stp端测量0–5V、200 Hz、约50%占空比波形；根据“未收到”或“收到但未执行”分支处理。
